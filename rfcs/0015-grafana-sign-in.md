# RFC-0015 Grafana sign-in through shpyrd

**Status:** provisional

**Owner:** unassigned

**Depends on:** RFC-0007 (implemented)

**Creation date:** 2026-09-22

**Last update:** 2026-09-22

## Summary

Grafana stops being public: it signs users in with the same accounts as the dashboard
(OpenID Connect against the cluster's issuer), anonymous access is off, the built-in admin
password is randomised. Platform admins become Grafana admins, everyone else a viewer.

## Motivation

Grafana ships today with `admin/shpyrd` and anonymous access, published at
`grafana.<domain>`. It shows every namespace's metrics.

### Goals

- One click from the dashboard header into Grafana, already signed in.
- Roles follow shpyrd's platform roles.

### Non-Goals

- Per-project scoping inside Grafana (it has no namespace-level authorization).

## Proposal

- Grafana `auth.generic_oauth` against the issuer (Dex when `auth-local` is enabled;
  configuration also accepts a direct provider from RFC-0058): client `grafana` registered
  as a Dex static client (secret generated by an installer hook), `auto_login: true`,
  `allow_sign_up: true`, scopes `openid email profile groups`.
- Roles: `role_attribute_path` mapping the `groups` claim (Dex passes groups for connectors
  that have them) and a `SHPYRD_GRAFANA_ADMINS` list of emails for local accounts →
  `GrafanaAdmin`; default `Viewer`. The membership controller (RFC-0008) writes the list of
  platform-admin emails into the Grafana values Secret when teams change.
- Anonymous access disabled; `admin` password random (Secret `grafana-admin`), printed only
  by `shpyrd cluster grafana-password` for break-glass.
- Without any login provider enabled, Grafana keeps the admin password only (no anonymous).

## Design Details

- kube-prometheus-stack values (`grafana.grafana.ini`) rendered from vars; redirect URI
  `https://grafana.<domain>/login/generic_oauth` added to the Dex client.
- The dashboard header link stays; Grafana's own login page shows one button "Sign in with
  shpyrd".

## Open questions

1. Should developers see Grafana at all (it exposes all namespaces), or only platform
   roles? Default: platform admins and viewers only; developers use the project's Metrics
   tab and RFC-0028 resource pages.
