# RFC-0046 Object storage extension

**Status:** implementable

**Owner:** unassigned

**Depends on:** RFC-0002 (implemented)

**Creation date:** 2026-09-22

**Last update:** 2026-09-22

## Summary

An `object-storage` extension giving the platform an S3-compatible bucket store: MinIO on
the local profile, the provider's service (S3) on cloud profiles, with per-consumer
credentials handed to other extensions (Loki logs, Postgres backups, platform backups).

## Motivation

Three RFCs need durable object storage; each configuring its own would triple the work
and the credentials.

### Goals

- `shpyrd extensions enable object-storage` and consumers get a bucket and credentials.
- Cloud profiles point at S3 without running MinIO.

### Non-Goals

- Exposing buckets to applications as a resource (a later resource type).

## Proposal

- Local: MinIO (single node, a RWO volume, `SHPYRD_OBJECT_STORAGE_SIZE` default 20Gi) with
  a console behind the sign-in later; root credentials generated by a hook.
- Cloud: `SHPYRD_S3_ENDPOINT`, region, bucket prefix; credentials by IRSA or a Secret.
- `ext.Deps` exposes `ObjectStore` (`Bucket(name) (endpoint, credentials)`): the extension
  creates a bucket per consumer (`shpyrd-logs`, `shpyrd-postgres-<project>`, `shpyrd-backups`)
  with a scoped access key, stored in a Secret the consumer's namespace can read.
- Cluster page: capacity used per bucket.

## Design Details

- MinIO via its Helm chart pinned; buckets and policies created with the `mc` admin API from
  the extension's reconciler.
